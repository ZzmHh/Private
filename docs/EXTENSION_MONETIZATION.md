# TikTok 插件 · 与网站订阅联动（变现说明）

凡梦 **插件不单独收费**，与 SaaS 网站 **同一账号、同一套餐**。AI 能力在服务端执行，插件只是登录后的「遥控器 + 页面读取器」，因此天然适合按订阅收费。

## 商业逻辑（推荐）

```
卖家安装插件（免费下载）
    → 插件弹窗登录凡梦账号（JWT）
    → 每次同步 / 生成话术 / 诊断 请求你的 API
    → 服务端校验：试用是否有效？套餐是否含 storeApiAgents？
    → 通过则扣每日额度；不通过则 402/403 + 引导去网站付费
```

插件本身可以 **免费上架 Chrome 商店**（降低安装门槛），**钱在网站订阅上收**——这是 B2B SaaS 常见做法。

## 当前代码里已实现的门禁

| 能力 | 服务端检查 | 说明 |
|------|------------|------|
| 试用 | `assertUserCanUsePlan` | 注册后 **3 天试用**，过期返回 402 |
| 套餐功能 | `ensureFeatureAccess(..., "storeApiAgents")` | **标准版 / 全托版 / 企业版** 可用插件 |
| 尝鲜版 starter | `storeApiAgents: false` | 登录后插件会提示升级 |
| 调用量 | `incrementUsage` | 按套餐 `dailyLimit` / 试用总上限 |

插件相关 API：`/api/extension/status`、`/snapshot`、`/cs/suggest`、`/analyze` 均已走上述校验。

## 你需要配置的生产环境

1. **部署网站 + 后端**（HTTPS）
2. 在服务端 `.env` 设置：
   ```env
   APP_PUBLIC_URL=https://你的前端域名
   ```
   插件「去网站订阅」会打开：`https://你的前端域名/#subscription`
3. 插件弹窗里 **凡梦 API 地址** 填你的后端，例如：
   - 同域：`https://你的域名`（若 API 与前端同站）
   - 或：`https://api.你的域名`
4. 在网站完成 **订阅 / 支付流程**（已有订单与 `simulatePayOrder` / 人工确认支付）

本地开发：

- 后端：`npm run dev:server` → `http://127.0.0.1:8787`
- 前端：`npm run dev` → 通常 `http://127.0.0.1:5173`
- `.env` 中 `APP_PUBLIC_URL=http://127.0.0.1:5173`
- 插件 API 地址填 `http://127.0.0.1:8787`

## 卖家侧体验

1. 安装插件 → 弹窗登录（与网站相同邮箱密码）
2. 弹窗显示：**试用中 · 3天免费试用** 或 **已订阅 · 标准版**
3. 无权限时：弹窗与卖家中心面板显示红色提示 + **「去网站订阅 / 续费」**
4. 付费后刷新 TikTok 页面即可恢复

## 定价建议（与现有套餐对齐）

| 套餐 | 是否可用 TikTok 插件 | 说明 |
|------|----------------------|------|
| 3 天试用 | ✅ | 拉新、体验客服 + 诊断 |
| 尝鲜版 99 | ❌ | 仅基础 Agent，促升级 |
| **标准版 299** | ✅ | **主推**：含插件 + 业绩/客服 Agent |
| 全托版 899 | ✅ | 多店、高频调用 |

可在官网定价页明确写：**「含 TikTok 卖家中心 Chrome 助手」**，避免卖家以为插件永久免费。

## 如何自测收费链路

1. 注册新账号 → 试用期内插件应可用
2. 管理员或改库把 `trialEndsAt` 设为过去 → 插件应提示订阅且按钮禁用
3. 网站订阅标准版（或 dev 环境模拟支付）→ 刷新卖家中心 → 插件恢复
4. 用尝鲜版账号登录 → 应提示「升级到标准版」

## 可选增强（未做 / 后续）

- 按店铺数加价（全托版 `multiStore` 已预留）
